# Portfolio Register

Internal editorial reference for the October 2026 portfolio review. This register helps maintain navigation, status language, and artifact boundaries; it is not a new research program, repository, public release, or theory connecting every item below.

**Reviewed:** October 7, 2026

## How to read the portfolio

AI has two distinct roles in this portfolio. It is a **research subject** in work on AI evaluation, risk, provenance, management, and practical literacy. It is also a **working tool** that may support research, writing, software development, or asset creation in otherwise independent work. Use of AI as a tool does not make every project AI research, establish a shared theory, or validate a project's claims. Each repository remains authoritative for its own methods, evidence, disclosures, release status, and reuse boundaries.

- The AI-Risk-Management README identifies [Practical AI Sense](https://honggaoc-star.github.io/practical-ai-sense/perspectives-on-ai.html) as broader human-use and governance motivation and [Evidence-Centered AI Evaluation](https://honggaoc-star.github.io/practical-ai-evaluation/working-paper.html) as a direct institutional foundation.

- Research-Lab records offer related paths through luck, institutions, systems, outcomes, and life as lived. Each publication retains its own question, evidence, status, and limits.
- APRM and PAIM are separate applications with different subject matter, operating boundaries, releases, and permissions. Similar naming does not imply a shared product or permission boundary.
- Practical Life Sense remains an independent family-reading project; its use of AI-generated illustrations is a tool disclosure, not a claim that the project belongs to the AI research program.

## Editorial rules

1. Keep one authoritative home for each artifact, release, and project record.
2. Link to canonical records rather than copying papers, release materials, or project content into the website repository.
3. Distinguish a current publication or release from exploratory, proposed, archived, or deferred work.
4. Preserve established public URLs and compatibility paths unless a separately reviewed change is necessary.
5. Carry forward each repository's license, distribution, privacy, safety, and reuse boundaries; a portfolio link does not broaden permission.
6. Describe intellectual relationships as reader navigation unless the authoritative sources support a stronger claim.

## Quarterly update procedure

At each quarterly portfolio review:

1. Check every default-branch README and any controlling publication, completion, or release record linked above.
2. Update status language only when the authoritative record has changed; use its exact version and boundary language.
3. Test repository, public-destination, and documentation links without replacing established URLs unnecessarily.
4. Add a project only after its authoritative home and role are clear; remove or archive an entry only through an explicit portfolio decision.
5. Record the new review date and summarize material register changes in the pull request. Do not duplicate artifacts or expand a project's claims while updating this file.
